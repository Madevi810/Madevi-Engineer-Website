# Release Readiness

Copy this checklist to `Foundation/12-Handover/Release-Readiness.md` when a legacy workspace does not contain it. A release is not stable merely because code compiles or a preview looks correct.

## Checks

- [ ] Scope, change requests, and Foundation handover are current
- [ ] Tests and acceptance evidence are linked
- [ ] Security, privacy, accessibility, and performance risks are reviewed
- [ ] Deployment, rollback, backup, and monitoring are appropriate to the project mode
- [ ] Known limits and deferred work are visible to the developer
- [ ] Implementation history, traceability, and changelog are updated

## Classification

- DRAFT: internal planning or incomplete evidence
- PREVIEW: review/testing only; not production-ready
- LIMITED: usable with explicitly recorded limits
- STABLE: developer approved with evidence and operational readiness
