# Stage 14 — Change Management

Use this stage when a developer remembers a feature, objective, integration, UI/UX direction, or operational requirement after earlier Foundation decisions or implementation work already exists.

Every request begins as a record in `Requests/`. Assess impact before changing code or approved decisions. The developer chooses one outcome:

1. approve for the current stage;
2. revise the affected Foundation decisions and re-approve;
3. defer to `Backlog.md` for a future release;
4. reject with rationale.

High or critical impact requires a new stage review. A change that alters the primary objective, major module boundary, security model, data model, deployment mode, or committed public behavior requires a Foundation revision and new implementation gate.
