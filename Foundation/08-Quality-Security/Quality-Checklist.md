# Quality and Security Checklist

- [ ] Roles and permissions are specified.
- [ ] Data classification and privacy impact are known.
- [ ] Secrets are named but never committed.
- [ ] Critical paths have acceptance criteria and test coverage.
- [ ] Error, loading, empty, and permission-denied states exist.
- [ ] Mobile, desktop, and accessibility requirements are defined.
- [ ] Performance budget is set for user-facing pages.
- [ ] Backups and rollback are defined before production.
- [ ] Asset licenses, provider terms, and watermark/metadata constraints are reviewed.
- [ ] Brand/content quality rules reject generic filler and unreviewed placeholders.
